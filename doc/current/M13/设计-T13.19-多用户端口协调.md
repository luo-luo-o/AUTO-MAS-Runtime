# 设计与计划 T13.19 多用户端口协调

- 契约：[增补 1 C12](../../契约补充-v1-增补1.md#c12受监督端口由-runtime-注入) 的 2026-09-24 修订
- 范围：Runtime 的隐式端口分配；Electron 保留现有单用户会话单例锁，并消费 `backend.run/running` 的 `baseUrl`

## 问题与目标

两条 `backend supervise --mode development` 同时启动时，都可能在后端绑定前探得默认端口 36164 空闲，随后一条以端口冲突退出。Windows 还允许回环地址与通配地址重复试绑定，单靠 `net.Listen("127.0.0.1:<port>")` 会误判已有后端的端口。

隐式端口优先使用模式默认值；已被监听时让系统选择可用端口。多个 Runtime 进程需跨 Windows 用户会话串行化「选端口到后端就绪」这段时间。端口写回同一份监督请求，健康检查、关闭地址、`baseUrl` 与自动重启均沿用它。

## 边界与失败语义

- 显式 `--port` 始终固定，不参与自动避让；单用户 Electron 的 `requestSingleInstanceLock()` 不变。
- 协调锁在后端就绪后或启动失败收口时释放，不持有到整个监督生命周期结束。等待可由上下文取消，Mutex 随进程退出由 Windows 回收。
- 锁不可用时在启动前失败；不以另一个实例的健康响应冒充本实例就绪。仍以现有 `BACKEND_SPAWN_FAILED` 报告协调失败，不新增协议字段或错误码。
- Runtime 开发态和后端开发态分别由 `AUTO_MAS_TELEMETRY=disabled`、`.env` / `AUTO_MAS_ENV=development` 保证不上报 Sentry。

## 验证

1. 单元测试覆盖默认端口已被通配地址监听时的避让，以及显式端口不改写。
2. 编译真实 Runtime，通过两个独立受管根同时监督同一开发源码目录；两条 `backend.run/running` 的 `baseUrl` 不同，健康接口均 `ready=true`，stdin 关闭后两个 Runtime 均以 `OK` 退出。
3. 不同 Windows 用户会话的 Electron 启动与单例行为由用户在本机手动验收。
